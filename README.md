# Трекер откликов

Учёт вакансий, откликов и событий по ним. Написан под собственную задачу: когда разборов вакансий стало больше десятка, markdown-файлы перестали давать ответ на вопросы «где висит без ответа неделю» и «что из отправленного дошло до интервью».

**Стек:** Python, FastAPI, SQLAlchemy 2.0, PostgreSQL, Jinja2.

## Что умеет

- CRUD вакансий с компаниями, условиями, приоритетом и ссылкой на файл разбора.
- Лента событий по каждой вакансии: отклик, анкета, созвон, интервью, тестовое, оффер, отказ.
- **События двигают воронку сами:** добавили «интервью» - статус вакансии сменился, добавили «отклик отправлен» - проставилась дата отклика.
- Аналитика: сколько откликов, какая доля дала ответ, что висит без движения больше недели, какие действия запланированы на ближайшие дни.
- Фильтры по статусу и поиск по компании и роли.
- Импорт существующих разборов из markdown-индекса.
- Тёмная тема: переключается кнопкой в шапке, выбор запоминается, по умолчанию берётся системная.
- Календарная лента `/calendar.ics`: ближайшие действия и назначенные созвоны уезжают в Google Calendar.
- Колонка «Фидбек»: что сказали после созвона или собеса и что сделал на этапе. Правится прямо в таблице, есть готовые пометки с датой - ответил ИИ-помощнику, прошёл скрининг, заполнил форму.
- **Конструктор рассказа о себе** - см. ниже.

## Рассказ о себе

Самопрезентация хранится не текстом, а структурой: «кирпичи» (якорь, места работы, куда двигаюсь), к каждому - добавки, помеченные типом вакансии, плюс акценты, крючки и ответы на частые вопросы.

Из этой структуры собираются три версии по скрипту:

| Сборка | Что входит |
|---|---|
| **40 секунд** - HR просит коротко | Только опорные предложения, короткий эпизод пропускается, добавок нет |
| **2 минуты** - основной вариант | Опорные предложения плюс 2 добавки на место |
| **4-5 минут** - технарь просит подробно | То же, но добавок до 4 на место |

Сборка учитывает три измерения:

- **Сколько времени** - три версии выше.
- **Какая вакансия.** Тип (`dev` / `support` / `ai`) задаётся у вакансии или угадывается по названию роли. От него зависит, какие добавки поднимаются наверх, и какой вариант блока «куда двигаюсь» подставится.
- **Кто слушает.** HR слышит результат, масштаб и людей; технический интервьюер - как именно устроено и что решал. Каждая добавка помечена аудиторией, и переключатель меняет набор.

**Причины ухода хранятся в двух слоях:** что произносится вслух и как было на самом деле. Второй слой закрыт и нужен только чтобы помнить контекст - в нём же записано, почему вслух так говорить нельзя. Критика бывшего руководства читается как риск, даже когда она справедлива.

**Вопросы к работодателю** идут отдельно для HR-этапа и техсобеса, и делятся на два вида: узнать важное для решения и показать заинтересованность. Плюс блок «именно по этой вакансии», который выводится из её данных: не указана вилка, неизвестен формат, есть пометки со знаком внимания в разборе.

В интерфейсе: у вакансий, где уже есть контакт с работодателем (скрининг, интервью, оффер), появляется кнопка **«рассказ о себе»**.

Наполнение структуры:

```bash
python seed_pitch.py
```

Источник содержания - `career-notes/Work_Experience.md`, часть «Рассказ о себе - конструктор». Скрипт идемпотентный: перезаполняет таблицы заново.

## Запуск

```bash
python -m venv .venv
.venv\Scripts\activate           # Windows
pip install -r requirements.txt

copy .env.example .env           # и вписать пароль от PostgreSQL
uvicorn app.main:app --reload --port 8300
```

Интерфейс: <http://127.0.0.1:8300/>
Документация API (Swagger): <http://127.0.0.1:8300/docs>

База создаётся автоматически при первом запуске. Перед этим нужно создать саму БД:

```sql
CREATE DATABASE vacancy_tracker;
```

## Импорт из markdown

```bash
python -m scripts.import_from_markdown
```

Читает индекс разборов, разбирает строки таблицы и наполняет базу: приоритет, компанию, роль, формат работы, зарплатную вилку, вердикт и путь к файлу. Дата отклика для уже отправленных берётся из имени файла разбора. Повторный запуск не создаёт дубли.

## Структура

```
app/
  models.py     доменные модели: Company, Vacancy, Event, Contact
                структура рассказа: PitchBlock, PitchAddon, TrackFocus, PitchTip
                вопросы по этапам: StageQuestion
  schemas.py    Pydantic-схемы запросов и ответов
  crud.py       вся работа с БД: статистика и сборка рассказа под вакансию
  database.py   подключение, сессии, чтение .env
  main.py       эндпоинты, страница интерфейса, календарная лента
scripts/
  import_from_markdown.py   импорт разборов
seed_pitch.py   наполнение структуры рассказа о себе
templates/
  index.html    одностраничный интерфейс
```
